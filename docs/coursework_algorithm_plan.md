# 战斗姐妹：课程项目算法与硬件方案

更新：2026-11-18。用户要求：方法尽量前沿，优先实际胜率；本机只有
i5-1135G7、16 GB 内存和 Iris Xe，可通过 Colab CLI 使用 RTX PRO 6000。
这是实验方案；世界模型和蒸馏部分尚未实现，不能作为已经完成的成果。

## 已验证的基础

- Windows 游戏 1.5.78.11833 + Modding API v77 + 当前源码编译的 HKRLEnvMod 0.8.0。
- 专用 3 号槽，标准寻神者能力：9 格血、纯粹骨钉基础伤害 21、完整技能。
  当前只装备虚空之心；各算法必须使用同一存档、护符和难度。
- 目标是 `GG_Mantis_Lords_V` / `sisters_of_battle`，即战斗姐妹。
  当前难度为 Attuned；“战斗姐妹变体”和 Ascended/Radiant 难度是两个概念。
- 直接加载、Boss 自然激活、正常血量、动作控制、连续重开已实机通过。
  证据：`runs/game-setup/sisters-live-validation.json`。
- MLP PPO 和小型实体注意力 GRU PPO 分别完成 512 步真实采样和一次更新。
  这些是链路试验，不是高胜率训练结果。

## 文献判断与选型

1. [OC-STORM，ICLR 2026](https://oc-storm.weipuzhang.com/)：直接包含空洞骑士
   实验，是最贴近任务的研究参照。对象表示与世界模型已有明确先例，不能把
   “加注意力/用对象表示”单独包装成新算法。
2. [OC-STORM 论文 v2](https://arxiv.org/abs/2501.16443v2)：论文使用视觉对象
   特征，包含普通 Mantis Lords；其设置、观测、奖励、动作频率与本项目不同。
   本项目读内部状态，不能直接拿论文胜率宣称超越。
3. [官方硬件说明](https://github.com/weipu-zhang/OC-STORM/blob/main/docs/hollow_knight.md)：
   原实现把视觉提取、策略推理与世界模型放在 GPU 端，推荐至少 3090 级设备，
   异步脚本使用两块 GPU。因此原样运行不符合本机 CPU 执行约束。
4. [DreamerV3，Nature 2025](https://www.nature.com/articles/s41586-025-08744-2)：
   参考潜在世界模型、想象学习及数值稳定化方法。
5. [STICA，AAAI 2026](https://arxiv.org/abs/2511.14262v3)：参考实体交互建模。
   [Dreamer 4](https://arxiv.org/abs/2509.24527)作为扩展阅读，其大型视觉模型路线
   不直接作为本项目的执行端。

## 主线：对象世界模型教师与轻量循环策略

研究问题：在真实采样较慢、执行端只有 CPU 的条件下，云端世界模型能否帮助
本地小策略更快学会战斗姐妹的交叉攻击规避，同时提高胜率？

执行分工遵循 [ADR-0004](adr/0004-local-inference-remote-training.md)：

| 部分 | 运行位置 | 工作 |
|---|---|---|
| 游戏、Mod、Gym、策略推理 | 本机 Windows | 结构化观测到动作的完整实时闭环 |
| 轨迹整理与上传 | 本机/WSL | 按批次传输，携带 episode、policy version、elapsed ticks |
| 世界模型、想象轨迹、教师与学生更新 | Colab 单块 GPU | CUDA 批训练与校准，不逐帧返回动作 |
| 发布与载入 | GPU 到本机 | 校验哈希，在约定边界更新学生权重 |

学生先用 `sisters_cpu_gru.yaml` 的小型实体注意力 + GRU；世界模型只存在于
训练端。学生的 CPU 延迟和实际采样 SPS 是模型扩容前的验收条件。
当前建议目标为推理 P95 不超过 20 ms。实测在游戏同时运行、系统空闲内存约
1.2 GB 时，285.84 万参数学生的合成观测推理中位数约 19 ms；单线程 P95
约 32 ms，双线程 P95 约 64 ms，尚未达到该工程预算。启动脚本因此改为单线程。
这两次测试有系统负载差异，不能视作严格的线程数因果实验。正式训练前仍要
在真实观测与固定负载下做延迟验收；不能用远端 GPU 的吞吐替代此检查。

教师使用结构化实体序列建立状态转移、奖励、受伤与终止预测；实体间的交互
用于表示三姐妹和飞行物对玩家的共同威胁。世界模型产生短时想象轨迹来更新
教师策略，再在真实观测序列上将教师动作分布蒸馏到学生。学生同时保留真实
轨迹的循环 PPO 更新，以便实测世界模型偏差对控制的影响。

拟检验的改进是**不确定性门控的策略蒸馏**：世界模型在某段战斗上的预测误差
或模型分歧较大时，降低这段教师监督的权重；可信度较高时增加教师监督。
损失候选形式为：

`L_student = L_recurrent_PPO + lambda * mean(w(u) * KL(pi_teacher || pi_student))`

其中 `u` 在独立验证轨迹上校准；`w(u)` 必须固定规则、记录参数，并与不门控
的蒸馏作对照。它是待验证的课程项目改进，不声称具有未经查证的首创性。

## 防止实验结论失真

- 用户新增目标是尽量无伤。最终报告同时展示整场胜率、无伤胜率和累计受伤；
  无伤胜率的分母是全部评估回合，回血不抵消已受伤事件。训练先获取有效攻击
  和获胜能力，再在保持胜率的条件下优化风险；当前基线奖励不在训练中途修改。
  后续世界模型的受伤预测可用于风险约束，但是否提高无伤率必须做独立消融。

- 真实死亡保持 episode 终止语义；不能把受伤训练技巧直接算作真实战败。
- 所有训练序列不跨 episode；实体对齐通过稳定 ID 做匹配，不能把临时 ID
  本身当作“第几位姐妹”的答案。消失/出现实体分别处理，并使用 entity mask。
- 使用实际 `elapsed_ticks` 解释预测时距，避免可变动作持续时间导致标签错位。
- 阶段采样只作训练数据平衡；最终评估必须从正常完整战斗起点开始。
- 教师使用更多信息时，另做相同观测的对照，区分信息优势和算法改进。
- 保留 privileged/reduced 观测分组；结构化状态结果不称为纯视觉或人类观测结果。
- GodSeekerPlus 只开启 UnlockAllModes；伤害减半、无限魂、无限连战和加速等
  游戏性修改均关闭。任何后续护符配置要统一、冻结并写入实验记录。

## 对比与推进顺序

1. 本机真实链路与计算预算：已完成环境验收和两类策略短训练。
2. 固定预算训练 MLP PPO 与小型 Attention-GRU PPO，建立初始胜率和 SPS 曲线。
3. 用真实轨迹训练对象世界模型，检查多步预测、受伤预测校准和阶段覆盖。
4. 实现无门控教师蒸馏，再加入不确定性门控；在相同真实交互预算下比较。
5. 至少比较 MLP PPO、GRU PPO、世界模型教师蒸馏、门控蒸馏；做去掉实体关系、
   去掉门控和匹配网络容量的消融。资源不足时优先保留直接检验改进假设的对照。
6. 候选方案至少 3 个训练种子；最终胜率使用独立评估种子/回合并报告置信区间。
   报告实际决策步数、物理 ticks、墙钟时间、训练 GPU 时间和 CPU 推理延迟。

主指标依次是胜率、受伤量、成功回合用时、真实交互样本效率。训练奖励不能
替代胜率。最终演示采用实际评估最好的模型，不预先宣称世界模型一定胜过 PPO。

## 单体阶段的离线验货（2026-11-19）

两轮各有 201 批、102,510 个决策。第一轮 `long-timing` 整轮用于拟合，第二轮
`long-platform` 整轮留出。使用当前玩家状态、螳螂受击框相对位置和速度、敌方飞镖数量、
最近飞镖的相对位置和速度，以及当步策略输出的动作。用直方图梯度提升树预测接下来
1 或 15 个决策间隔内是否观测到玩家或同一只螳螂的 HP 下降。模型只看到预测起点的
状态与动作。15 步内的后续动作由当时采样的 PPO 策略决定。

| 预测范围 | 留出窗口数 | 玩家掉血窗口 | 玩家掉血 AP / 常数基线 | 螳螂掉血窗口 | 螳螂掉血 AP / 常数基线 |
|---|---:|---:|---:|---:|---:|
| 下一决策 | 101,406 | 4,045 | 0.676 / 0.040 | 1,087 | 0.385 / 0.011 |
| 未来 15 决策 | 86,590 | 49,514 | 0.787 / 0.572 | 13,387 | 0.356 / 0.155 |

AP 是平均精度，越高表示越能把真正发生掉血的窗口排在前面。常数预测的 AP 等于
该目标在留出集的发生率。每个窗口都在同一批、同一游戏实例、同一回合、同一螳螂
ID 内，时间严格递增，排除终止与截断转移。因此最后一次致死伤害未计入。标签取
相邻观测的 HP 净下降，无法区分伤害来源，也可能漏掉一个决策间隔内被治疗抵消的伤害。
15 步窗口有重叠。这是两个既有策略采样分布之间的预测检验，覆盖单体阶段。

复现时在安装了项目和 `scikit-learn` 的 Python 环境运行：

```bash
python scripts/probe_sisters_replay.py \
  --train runs/training/sisters-overnight-1119/long-timing/rollouts \
  --holdout runs/training/sisters-overnight-1119/long-platform/rollouts
```

下一次世界模型实验应同时报告逐步推演 1 / 5 / 15 步的实体位置误差和掉血事件 AP，
用位置保持与上表的直接分类器作对照，实测不同动作是否改变预测。记录新轨迹时从真实
受伤事件生成 `life_loss`，保留游戏终止标志；训练时比较启用和关闭掉血价值截断。
OC-STORM 的空洞骑士环境从受伤日志设置该标志，学习器使用它截断价值，环境仍然
继续到真实结束。该做法对本项目进攻和存活的影响需要原速实战检验。实战分别报告
场均伤害、过第一只、整场胜场、无伤胜场。想研究多体阶段，还需要取得该阶段的真实
转移。[上游环境](https://github.com/weipu-zhang/OC-STORM/blob/main/envs/hollow_knight/env_wrapper.py)
与[采样代码](https://github.com/weipu-zhang/OC-STORM/blob/main/train_async.py)。

## 单体世界模型与掉血截断实机对照（2026-11-19）

继续用 `long-timing` 拟合，整轮 `long-platform` 留出，各 102,510 个真实决策。
历史窗口含四次观测和中间三次动作。GRU 从这个窗口编码的状态起步，之后只读动作。
三个独立种子 17、41、73 各在 Colab RTX PRO 6000 更新 1,500 次，批量 384。
监督目标为小骑士位置、螳螂受击框中心、螳螂 FSM、双方 HP 净下降和真实终止标志。
位置和掉血标签排除没有下一观测的末步，终止预测仍使用真实末步标志。这批档案只覆盖单体开局。

| 推演决策数 | 留出窗口 | 小骑士位置误差 / 保持原位 | 螳螂位置误差 / 保持原位 | 小骑士掉血 AP / 发生率 | 螳螂掉血 AP / 发生率 |
|---:|---:|---:|---:|---:|---:|
| 1 | 98,140 | 0.61 / 1.20 | 2.11 / 3.02 | 0.623 / 0.040 | 0.650 / 0.011 |
| 5 | 93,859 | 1.99 / 3.23 | 4.97 / 11.63 | 0.705 / 0.204 | 0.606 / 0.054 |
| 15 | 83,567 | 3.18 / 4.63 | 9.37 / 13.67 | 0.777 / 0.572 | 0.615 / 0.155 |

位置误差为平均欧氏距离，单位是游戏场景单位。掉血 AP 评估窗口中是否至少发生过一次
HP 下降。留出推演按历史 PPO 实际执行的动作序列进行。预测到第 15 步时，FSM 命中率为
42.5%，沿用当前 FSM 的命中率为 10.7%。

只替换一个合法原子输入，并要求整套替代按键在训练中至少出现 20 次。66,610 个可反向样本中，
真实方向和反方向对下一次实际横坐标的平均绝对误差分别为 0.415、0.557。允许切换挥刀按钮
的 17,492 个样本里，只有 53 次下一步螳螂掉血。输入真实挥刀选择与翻转选择的 AP 分别为
0.061、0.046。在随机选取的 500 个下一步小骑士掉血样本中，可加跳跃、可加冲刺、可反向的
分别有 85、97、345 个。替换后模型预测的平均受伤概率分别变化 +4.46、+1.17、−0.65 个百分点。
反向移动明显改变了预计位移。这些概率变化缺少同一局面下另一动作的实机结果。

两份策略共用 24,000 个真实训练起点、三个冻结模型、12 步想象长度和同一蒸馏批次顺序。
候选为出现最频繁的 64 个原子按键组合，其中 13 个含挥刀，覆盖有历史窗口的原子训练动作
79.0%。每个候选改变第一步，余下动作来自另一个尽量匹配螳螂 FSM 的训练窗口，同一起点的
候选共用后续动作。按三个模型的平均回报减一个标准差排序，并保留行为先验。回报以螳螂掉血
事件 +6.3、小骑士掉血 −12、本轮失败终止 −100 近似，无法还原每次伤害的金额。当前数据
没有胜场，后续包含胜场时需要区分胜利和死亡事件。两组物理终止都截断，
其中一组还用预计受伤概率衰减后续价值。部署时两组都在当前合法组合里选概率最高者。

复现实验时先用 `scripts/pack_sisters_sequences.py` 分别压缩两轮的 `rollouts` 目录。
将两个 NPZ 传到训练机，然后训练世界模型和两份策略。

```bash
python scripts/fit_sisters_dynamics.py --train train.npz --holdout holdout.npz --output models --device cuda
python scripts/train_sisters_imagination.py --train train.npz --models models --output models --device cuda
```

将模型下载到游戏电脑，在 3 号槽执行
`python scripts/eval_sisters_imagination.py --models models --output live`。
同一窗口每轮各打一场，两组先后顺序逐轮交换。Unity 随机数未锁定。

3 号槽、Attuned、原速、单个游戏窗口、相同护符和原版任务。先用冻结的
`selected-follow-201` 在同一窗口重测 10 场，再完成共 20 场交替对照。
三组的 Python 评估种子列表均为 33410–33419。过首只用进入多本体阶段计数，
三组最高伤害也均低于首只的 500 HP。无伤胜利三组均为零。

| 策略（各 10 场） | 场均 / 最高伤害 | 打出伤害 | 过首只 / 胜场 | 平均存活游戏秒 | 掉血点数（本体 / 飞镖 / 地刺） | 每游戏秒决策 |
|---|---:|---:|---:|---:|---:|---:|
| 冻结 PPO | 137.3 / 229 | 10 | 0 / 0 | 39.77 | 43 / 46 / 1 | 10.89 |
| 想象策略，掉血继续累计价值 | 0.0 / 0 | 0 | 0 / 0 | 46.57 | 14 / 36 / 40 | 14.33 |
| 想象策略，掉血截断价值 | 2.1 / 21 | 1 | 0 / 0 | 42.52 | 27 / 21 / 42 | 14.79 |

两份策略都能左右移动，各自在 10 场内分别发出左 / 右移动 2,987 / 2,950 次和
2,800 / 2,532 次。含挥刀输入的决策却从 PPO 的 16.46% 降到 0.63% 和 0.67%。
单窗口运行配置相同，轻量策略实际出决策更快，和 PPO 的差距包含部署节奏的影响。
同轮两组新策略实战均未达到延长训练的标准。保留旧 PPO 为对照，下一轮应保留它的
移动和平台落点处理，单独检验动作掩码允许时的挥刀选择，同时核对地刺扣血。

在留出集中另取 80,330 个有四次历史观测、三步有效后续的原子动作起点。旧 PPO 实际挥刀
占 17.3%。在相同状态和动作掩码下，两份蒸馏策略贪心选择挥刀的比例分别为 5.1%、
5.7%。其中有 13,916 个旧 PPO 选择挥刀的起点，64 项候选只覆盖这些完整按键组合的
49.7%。在随后三步螳螂确实掉血的 932 个挥刀起点中，覆盖率为 57.6%。
这些是此前策略实际走过的轨迹，三步内掉血并不保证由第一步挥刀造成。

作为覆盖率对照，在训练集先去掉挥刀位、保留最常见的 64 个其余按键组合，再分别放回
出现过至少 20 次的挥刀开和关，得到 117 个合法性待逐帧过滤的候选。以完全相同的留出
样本衡量，挥刀组合覆盖率增至 72.0%，随后三步有伤害的挥刀组合覆盖率增至 76.9%。
这组对照使用了更多候选，只测量动作表示能力。

原 PPO 的 `platform_preferences` 使用两侧地刺碰撞盒，估计落点和跳过地刺的可能性。
本轮压缩状态保留玩家绝对坐标、螳螂与最近飞镖的几何量，遗漏了地刺碰撞盒。
掉血训练标签也没有区分本体、飞镖和地刺。三种来源可从实机评估的受伤事件单独计数。
另只读核对了当前游戏程序集，常规受击无敌由 `HeroController.Invulnerable(float)`
协程用 `WaitForSeconds(duration)` 实现，Mod 尝试读取的三个剩余时间字段均未匹配。
这次比较使用无敌布尔标志，未使用或修复倒计时字段。

## 初期训练入口

训练入口见根目录 `训练使用说明.txt` 和
[ADR-0011](adr/0011-resumable-local-training.md)。本机默认先累计 10,240 步，
在固定真实交互预算下记录采样 SPS 与优化器耗时，再决定云端更新的收益。
