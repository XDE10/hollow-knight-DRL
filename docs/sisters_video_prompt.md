# 发给 Gemini 的战斗姐妹录像标注提示词

把完整 MP4 和第一段提示词一起发。收到回答后，在同一个对话依次发第二、第三段。最后把第三段输出的 JSON 保存下来。需要分批时可以按战斗阶段拆，同一条记录沿用同一个 ID。

## 第一段 · 看完整场，建立时间轴

```text
请分析我上传的《空洞骑士》战斗录像。我在训练一个能读取游戏状态的强化学习模型。它需要先活下来，同时把安全的空档转化成伤害。请替我标注真人在哪些时机选择了怎样的动作，以及这些选择在画面中产生了什么结果。

先告诉我你实际能读取的视频时间范围。如果只能看到抽样画面，请写明哪些判断会受影响。全程使用原视频从 0 秒起算的播放时间。只能定位到半秒就写半秒；有遮挡就给时间范围。不要把播放帧换算成游戏物理步。

先独立看完整场，给我一张紧凑的时间轴。划出入场、单体交手、转场、多体交手、最后一个活跃敌人退场、战后动作和菜单。用场景、敌人动作、血条变化等画面证据支持每个边界。如果片段有剪辑、变速、按键叠层、血条模组或装备画面，请注明能确认的内容。分别写出最多同时可见的活动本体和飞镖数，举一个时间点，说清坐在王座上的角色怎么处理。

选出最值得教给模型的片段，按时间排序。优先找相似威胁需要不同动作的对照，例如同为飞镖，这次能在地面等过去，另一次却需要起跳；同为螳螂落地，这次可以回刀，另一次另一只已经逼近。也找一组从左边和从右边处理同类招式的例子。没有看清的配对就直说缺什么。每条给起止秒、威胁来自哪里、小骑士先后做了什么、结果、最清楚的证据时刻。
```

## 第二段 · 复核具体动作和反击机会

```text
请回看刚才挑出的片段。每段从危险出现前看到动作结束后的落点或下一次威胁。另请复核原片 12–14 秒、16–23 秒、38–51 秒、61–67 秒、118–125 秒；它们只是定位线索，请根据画面修正判断。保留能说明不同选择的片段，不够清楚的可以舍弃。

1. 区分三个时刻：玩家当时已经能看到的前兆、玩家第一次改变动作、结果第一次能被确认。把事后才知道的事情写在结果里。给每个时刻一个时间或时间范围和画面线索。
2. 多目标时在同一片段内给活动本体和飞镖分别编号，如 B1、B2、P1、P2。逐个写相对小骑士的方位、高低、接近还是远离、是否挡住落点。区分当前最危险的对象和实际攻击的对象。消失再出现后身份无法确认就换号；飞镖交叉时允许身份未知。不要把刀光、剑气或残影算成新敌人。
3. 记录地面小步、停步、转身、起跳、空中再次上升、冲刺、平砍、上劈、下劈后反弹和法术。分别说出位移方向、朝向、挥刀方向。区分下劈反弹、带翅膀的二段跳、向下法术：看挥刀弧、触点、速度变化、翅膀或落地特效。仅凭跳得高无法区分长按与二段跳。没有按键显示时，按键种类、按住时长和逐帧指令都允许未知。
4. 靠近地刺时，记录小骑士与平台边的位置、空中轨迹、起跳点与落点。观察是否停步、继续贴边输出、跨过危险或转身。不要预设到边必回头。若无法确认踩刺或落地安全，请保留未知。
5. 分开“挥了刀”“看起来命中”“有血条变化支持”“疑似其他来源造成输出”。多个本体共用或叠放血条时不要猜是哪一只掉了多少血。小骑士掉血另记：先检查面具变化，再判断本体、飞镖、地刺或来源不明；画面闪白本身不能确认受到伤害。
6. 找出能安全回刀的窗口，也标出主动放弃一次输出、提前换位的窗口。有相反例子就配对。写清会使动作失效的条件，例如第二只正在下砸、回旋镖即将折返、落点在刺上。推断玩家意图时，用“可能”并给证据。请检查装备页和异常长的刀光，标出可能依赖护符、法术、灵魂或满血的动作；只识别能确认的装备，区分菜单光标和实际装备栏。

最后按优先级给我三条可在游戏里复现的战术。每条写触发条件、可观察动作、应中止进攻的信号、怎样同时核验避伤和命中，以及一个不能套用这条战术的片段或条件。不要写固定连招、奖励系数或假想按键轨迹。
```

## 第三段 · 导出可以回看的 JSON

```text
请以复核后的原片为准，输出一个可解析的 JSON 对象，不加 Markdown 围栏或前后说明。顶层放 duration_s、segments、clips、limitations。segments 里的每项含 phase、start_s、end_s、evidence。clips 只选有画面支撑的决策片段，每项使用下面这些字段。

id：唯一短 ID。start_s、end_s：原片秒数，数字。phase：single、multi 或 uncertain。cue_s、response_s、outcome_s：分别为前兆、首次反应、结果的秒数，看不清填 null。timing_uncertainty_s：按实际读片精度估计，未知填 null。
threats：数组，每项含 local_id、kind（body 或 blade）、relative_position、motion。primary_threat 和 attack_target 引用这一片段内的 ID，未知填 null。
player_before：地面或空中、平台区域、当前运动。actions_seen：按时间排序的可见动作数组。edge_and_landing：起跳或离开的位置、落在哪里、与地刺的关系。
attack_result：no_attack、swing_only、likely_hit、hp_drop_visible、unknown 之一。player_hurt：yes、no_visible_loss、unknown 之一。hurt_source：body、blade、spikes、mixed_unknown 或 null。visual_evidence：列出关键时刻以及画面变化。inferred_intent：可能的目的，与观察分开。confidence：high、medium 或 low。ambiguous：尚存的其他解释。paired_clip：适合对照的另一条片段 ID，没有则填 null。

复核所有引用、时间边界和时序。将高置信度且值得实机复现的片段 ID 放入额外顶层数组 reproduce_first。把样本稀少、左右方向失衡、装备条件不明、战后动作、多种解释仍然成立等情况写到 limitations。不要凑够条数，不要给我们捏造游戏坐标、精确伤害、无敌帧、输入键或按键时长。
```
